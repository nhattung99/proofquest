# Security status

Dependency audit after install: initially 20 findings including one high in transitive ws. Applied an API-compatible ws 8.x override under @ethersproject/providers; installed patched ws 8.22.0. npm then reported 19 remaining findings (14 low, 5 moderate), inherited through the official SDK's ethers/Solana dependency graph. These remain unresolved and are a public-release review item; no blanket force-upgrade or SDK replacement was performed. Local checks passing do not constitute a clean dependency audit.

This is a localhost proof harness, not a production service. appSecret is server-only; environment files are ignored. Signed requests are built on the server from fixed configuration. Requests require a loopback hostname, matching Host, same Origin for POSTs, and explicit local enablement. Host checks are containment, not authentication. Bind the server to 127.0.0.1 and never expose it through a tunnel/proxy.

The experiment does NOT prove wallet ownership. Its attempt store/rate limit are in-process, unsuitable for multiple workers or Vercel. Attempts are consumed synchronously once, including failed verification, and expire in five minutes. Production requires durable one-time challenges, authenticated sessions, atomic database uniqueness, CSRF controls and distributed rate limits.

No claims/points endpoints exist. Rewards remain disabled even for a genuine proof. A valid Primus signature is checked independently from source/resolver policy. Template ID is absent from the signed attestation; a template label in a challenge does not independently prove Hub template identity. No raw proof/data storage, user Web2 credential collection or token rewards are implemented. X screen_name is disclosed to the app/server during verification, and the bundled SDK console calls and optional eventReport telemetry are suppressed by scripts/primus-privacy-loader.cjs; browser/extension diagnostics are outside this application’s control. Do not claim complete privacy.

Before release: review upstream signing serialization, message handling, dependencies and telemetry; confirm template integrity and signed challenge behavior with live evidence; implement SIWE and durable persistence; reject future/stale proofs and cross-user reuse; constrain every field used for eligibility; ensure external account reuse policy; test concurrent transactions and secret-free browser bundles. Configure secure cookies, error redaction, headers and production environment separation. Do not publish the local harness as a reward service.


Current X policy: owner-confirmed Marketplace ID is fixed in request configuration. Signature, freshness, one-time challenge, recipient, strict endpoint, field/path and screen_name syntax are enforced. Expected resolver parseType is deliberately unpinned and returned as a limitation; no value was guessed. Template identity is request-pinned, not independently present in the signed output. Source/resolver checks are mandatory, not optional environment configuration. There is still no wallet authentication or durable cross-user reward protection. No reward claims exist.


Fix/polish update: Next.js and its ESLint config are now 16.4.6. npm audit currently reports 26 low/moderate findings, no Next entry and no high/critical findings. Cancel revokes a local attempt and ignores late client results; protocol abort is not guaranteed by the SDK. Conditions diagnostics are allowlisted/redacted, development-only and unavailable from production. The live PQ_CONDITIONS mismatch was resolved by validating the official reveal_id=screen_name metadata, with genuine user-confirmed acceptance on 2026-11-23; no condition or signature check was bypassed and no rewards were enabled.


Public verification preparation, not deployed: public mode now requires an exact HTTPS origin, enabled flag, server-only credentials and shared Redis REST. Anonymous Secure/HttpOnly cookies bind attempt consumption to the browser session. A single Lua operation checks session ownership and consumes an attempt; rate counters use atomic increments with TTL. Limits are per session and Vercel-provided IP; identifiers are HMACed. Public storage errors fail closed without memory fallback. No raw proof/account data is stored. Underlying Primus verification policy is unchanged and rewards stay disabled. This is still not SIWE or a claim/reward backend. Real Redis concurrency and public Vercel E2E remain unverified pending credentials/approval; see PUBLIC_VERIFICATION.md.
